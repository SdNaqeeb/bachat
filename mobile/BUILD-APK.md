# Building the Bachat APK — manual guide

A permanent, free, signed release APK. No EAS servers, no build credits, no
30-day expiry, no Android Studio, no admin rights.

**Short version:** `npm run apk` (once the one-time setup below has run).

---

## Why not EAS?

EAS builds work, but on the free plan Expo deletes the build **artifact**
after ~30 days — that is the "expires in 13 days" countdown on expo.dev. The
APK itself never expires; only Expo's download link does. Building locally
removes the link entirely and costs nothing.

This pipeline is ported from IntelliVault, a sibling project on this machine
that solved the same problem first. The JDK and Android SDK below are shared,
machine-wide installs reused as-is; everything Bachat-specific (keystore,
package name, output APK) is new and kept separate so the two apps' signing
identities never cross.

---

## What is installed where

| Path | What | Shared or Bachat-only |
|---|---|---|
| `D:\toolchain\jdk-17*` | Temurin JDK 17 (zip, no installer) | **shared** across projects on this machine |
| `D:\android-sdk` | Android SDK: platform-tools, platforms 35+36, build-tools 35+36 | **shared** across projects on this machine |
| `mobile\credentials\` | Bachat's own release keystore + passwords | **Bachat-only, gitignored, irreplaceable** |
| `mobile\android\` | generated native project | Bachat-only, gitignored, regenerated by every prebuild |
| `mobile\build\` | the finished APK | Bachat-only, gitignored |

The JDK and SDK are never reinstalled if already present — `setup-toolchain.ps1`
globs for `jdk-17*` and checks for `sdkmanager.bat` before downloading
anything. **The keystore is always Bachat's own** — it is never copied or
reused from IntelliVault or any other project. Mixing signing keys between
apps is not just bad practice, it is meaningless: each app is identified by
its own key, and Android will simply refuse to install one app's update using
another app's certificate.

Bachat's package is `ai.smartlearners.bachat`, its Gradle signing properties
are prefixed `BACHAT_UPLOAD_*`, and its output file is
`mobile\build\Bachat-release.apk` — all distinct from IntelliVault's, by
design, so the two pipelines can never collide even if both projects live on
the same machine.

## One-time setup (~15 min if the shared toolchain doesn't exist yet, ~10 sec if it does)

Run from `mobile\` in PowerShell:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\setup-toolchain.ps1
```

This does four things, each skipped if already satisfied:

1. **Finds or installs JDK 17** at `D:\toolchain\jdk-17*`. JDK **17**
   specifically — the Android Gradle Plugin rejects newer JDKs. If missing,
   downloads the Temurin zip (winget needs admin and fails on this machine).
2. **Finds or installs the Android SDK command-line tools** at
   `D:\android-sdk\cmdline-tools\latest\`. That exact nesting is mandatory —
   `sdkmanager` refuses to run from any other layout.
3. **Accepts SDK licences by writing their hashes directly.**
   `sdkmanager --licenses` is interactive and its `.bat` wrapper ignores piped
   input on Windows, so the licence hash files are written straight into
   `D:\android-sdk\licenses\`. If this step is skipped or fails silently,
   `sdkmanager` exits 0 but installs nothing — the script checks for
   `D:\android-sdk\platforms\android-36` afterward and throws if it's absent.
4. **Generates Bachat's own release keystore**, if one does not already
   exist, at `mobile\credentials\bachat-release.keystore`, with a fresh
   28-character random password, alias `bachat`, and identity
   `CN=Bachat, OU=SmartLearners, O=SmartLearners.ai, L=Hyderabad, S=Telangana, C=IN`.
   The password and alias are written to `mobile\credentials\keystore.env.json`.

> ## THE KEYSTORE IS IRREPLACEABLE — BACK IT UP NOW
>
> `mobile\credentials\` is gitignored on purpose: a keystore committed to git
> is a compromised keystore. But that also means **it exists nowhere except
> this machine's disk** until you copy it somewhere else.
>
> Android identifies an installed app by the certificate it was signed with.
> If `bachat-release.keystore` is lost:
>
> - **No future build can ever update an already-installed Bachat APK.**
>   Android will refuse the install with a signature mismatch.
> - The only recovery is to **uninstall Bachat from every device**, generate
>   a brand-new keystore, and do a fresh install — losing all local app data
>   in the process (there being no server-side account to restore from).
>
> **Copy `mobile\credentials\` to at least one place outside this repository
> and outside this machine** — an external drive, a password manager's file
> storage, a private cloud folder — before you forget. Do this before you
> ship the first APK to a real device, not after.

## Building (every time)

```powershell
cd "D:\Personal Repositories\Bachat\mobile"
npm run apk
```

Output: `mobile\build\Bachat-release.apk`

Manually, that script (`scripts\build-apk.ps1`) does:

```powershell
$env:JAVA_HOME = <the D:\toolchain\jdk-17* found on disk>
$env:ANDROID_HOME = 'D:\android-sdk'; $env:ANDROID_SDK_ROOT = 'D:\android-sdk'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"

npx expo prebuild --platform android           # --clean only if android\ is missing
powershell -File scripts\apply-signing.ps1      # re-wire release signing
& .\android\gradlew.bat -p .\android :app:assembleRelease --no-daemon
# then: apksigner verify --print-certs on the output, fails loudly if not
#       signed with the Bachat release key
```

### Expected build times

- **First build: expect roughly 40-50 minutes.** Gradle compiles native C++
  via CMake for all four Android ABIs (arm64-v8a, armeabi-v7a, x86, x86_64),
  north of 600 tasks. This is normal — do not interrupt it.
- **Later builds: a few minutes**, once Gradle's cache is warm.
- Running `expo prebuild --platform android --clean` (or deleting `android\`)
  resets that cache and costs the full first-build time again. `build-apk.ps1`
  only does a `--clean` prebuild when `android\` doesn't exist yet, precisely
  to avoid paying this cost on every build.

### Automatic signature verification

`build-apk.ps1` runs `apksigner verify --print-certs` on the finished APK and
**fails the build** if:

- the certificate says `CN=Android Debug` (signing was not applied — the APK
  would look fine and install fine, but could never update an existing
  Bachat install), or
- the certificate does not say `CN=Bachat` at all (wrong or missing keystore).

This check is automatic specifically because a debug-signed APK is otherwise
indistinguishable from a correctly signed one until the day someone tries to
install an update over an existing copy. You do not have to remember to run
this by hand, but you can:

```powershell
& D:\android-sdk\build-tools\36.0.0\apksigner.bat verify --print-certs `
  "D:\Personal Repositories\Bachat\mobile\build\Bachat-release.apk"
```

Expect `CN=Bachat, OU=SmartLearners, ...`.

### Install

```powershell
D:\android-sdk\platform-tools\adb.exe install -r `
  "D:\Personal Repositories\Bachat\mobile\build\Bachat-release.apk"
```

Or copy the APK to the phone, tap it, allow "Install unknown apps".

## How signing is wired (and why it is a script)

`android\` is gitignored and **rewritten by every `expo prebuild`**, so
signing config cannot simply live there — it would vanish. Two pieces make it
survive:

1. `android\app\build.gradle` gets a real `release` signingConfig that reads
   four `BACHAT_UPLOAD_*` Gradle properties, falling back to the debug key
   when they are absent.
2. `scripts\apply-signing.ps1` appends those properties (keystore path + the
   passwords from `credentials\keystore.env.json`) to
   `android\gradle.properties` after every prebuild, and patches
   `build.gradle` to add and use the `release` signingConfig.

**After any `expo prebuild --clean`, re-run `scripts\apply-signing.ps1`** — or
just use `npm run apk`, which does it for you.

`apply-signing.ps1` patches `build.gradle` by matching literal text from
Expo's generated template. That match can break on a future Expo SDK upgrade
if the template changes. Unlike a silent failure, this script **throws with
an explicit "could not find ... refusing to continue" error** rather than
falling through to a debug-signed build — see the comment at the top of
`scripts\apply-signing.ps1` for how to fix the match if that happens. All
files it writes are UTF-8 **without a BOM**
(`New-Object System.Text.UTF8Encoding($false)`); Windows PowerShell 5.1
otherwise injects a BOM that corrupts Gradle's parser.

## Gotchas hit while setting this up (inherited from IntelliVault, still true here)

| Symptom | Cause | Fix |
|---|---|---|
| `winget install ... exit 120` | needs admin / source not specified | use the Temurin zip instead |
| sdkmanager exits 0, installs nothing | licences not accepted | write the hash files (setup step 3) |
| `platforms;android-36` ignored | `cmd /c` splits on `;` | call `sdkmanager.bat` directly from PowerShell with quoted args |
| `'gradlew.bat' is not recognized` | `Push-Location` does not move the *process* working directory | invoke gradlew by full path with `-p <androidDir>` |
| `.ps1` parser errors on em dashes/smart quotes | Windows PowerShell 5.1 reads scripts as ANSI | keep `.ps1` files ASCII-only, no exceptions |
| Gradle file corrupted after a script writes it | PowerShell `Set-Content -Encoding utf8` adds a BOM | write with `[System.IO.File]::WriteAllText(..., New-Object System.Text.UTF8Encoding($false))` |
| APK installs but can't update the old copy | it was debug-signed, not release-signed | `build-apk.ps1` now checks this automatically — see "Automatic signature verification" above |
| "Hard link failed, doing a slower copy" | Gradle cache on `C:`, project on `D:` | harmless, just slower |

## Icons

Bachat has no source artwork yet. `scripts\generate-icons.mjs`
(`npm run icons`) draws a placeholder mark — a solid-colour rounded badge with
the initial "B" — into `assets\images\`, so the whole build pipeline is
runnable end to end before a real logo exists. Swap in real artwork later by
either editing the colours/initial at the top of that script, or replacing it
with a crop-based generator once real source art exists (see the comment at
the top of the script for the pattern IntelliVault uses for that case).
